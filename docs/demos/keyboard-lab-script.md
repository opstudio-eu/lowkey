# Keyboard lab and model retention video

Audience: the app owner. English UI and captions. Silent Android recording, approximately 2.5 minutes. Private Tailscale delivery. Synthetic draft only. Actual local Moonshine recognition uses bundled debug audio, explicitly disclosed before dictation; this is not a microphone test.

## Scenarios and evidence

- Open the lab from Models, type with the real keyboard, close, and reopen from Dictionary with the same draft. Source: SlimApp.kt and KeyboardTestSheet.kt. Underlying pages remain composed.
- Open Settings from the bottom bar, reach Voice, choose retention, and launch the lab without losing the settings scroll position. Source: SettingsScreen.kt and SettingsStore.kt.
- Start Moonshine Small dictation, finish it, and show loaded native resources. Choose immediate release while idle and show they unload without deleting the installed model. Source: LocalSpeechEngine.kt, ModelMemoryCard.kt, and DiskModelStore.kt.
- Close and reopen the lab on Diagnostics/About. Back behavior and process recreation are also checked outside the recording.

Prerequisites: Pixel API 36 only, Slim Keyboard enabled/selected, Moonshine Small already installed and verified, debug clip input chosen in Diagnostics. Restore microphone and 2-minute retention after recording. Do not start a second emulator. Only the lead drives this device; reviewers inspect files and captured evidence.

## Independent review

Accuracy pass: checked retention ownership, timers, settings persistence, and shared composition against source and passing test results. No blockers; draft copy narrowed to app exploration rather than permanent storage. Teaching pass: clarified the memory/loading trade-off, established the 2-minute default, and required 3-second unobstructed holds after transcription and release. Actual recording timings are allowed to expand for native loading. Both reviewers were read-only and did not use the sole emulator.
