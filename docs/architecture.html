1. Product goals

Slim keyboard

Four key rows with a suggestion strip. The globe sits immediately after ?123, in Samsung's position. About 240 dp tall.

Low-height voice mode

One row, about 56 dp: model picker, status, Talk/Stop, and the mic/keyboard toggle in the same slot in both modes. Live text appears in the editor.

Predictable voice lifecycle

Voice entry starts recording automatically, and the last mode is remembered. Switching to keys cancels recording and pending transcription.

Local English dictation

Dictate coding requests and explanations on the device. Live partial text is followed by one final commit.

Exact technical terms

Exact multiword terms such as T3 Code keep their spelling and case. Spoken-to-written phrase rules are optional.

Private and offline

Text and audio stay on the device. The network is used only for explicit model downloads.

2. Design principles

  1. Build our own code from proven designs. Write the code ourselves, guided by how FUTO Keyboard and the Moonshine voice fork solve the same problems. Do not copy their source. This keeps licensing simple and lets the architecture fit our narrower scope. Third-party libraries with permissive licenses, such as the Moonshine runtime, are acceptable dependencies.
  2. Pure logic stays independent of Android. The voice state machine, layouts, suggestions, phrase rules, and model catalog are plain Kotlin that runs in fast JVM tests. Android-specific code is a thin layer around them.
  3. Replaceable components behind interfaces. SpeechEngine, ModelStore, and Suggester have fake implementations today and real ones later. The mock demo is the first client of these interfaces.
  4. One owner for each piece of state. Each store exposes a StateFlow. The companion app and the input method run in the same process and share one AppGraph, so a dictionary edit appears in the keyboard immediately.
  5. Session-scoped, cancellable work. Each recording has a session ID. Every asynchronous result checks that ID before it touches the editor.
  6. Start with one module and clear packages. Extract Gradle modules when a boundary needs enforcement or isolates a heavy dependency.

3. System overview

The input-method service and companion app share one process. The service owns editor interaction. Pure-logic controllers decide what happens. Engines and stores do slow work off the main thread and report results as flows.

5. Key interfaces

These interfaces separate replaceable implementations. Each has a fake implementation now and a real one later.

// speech/ — modeled on the voice fork's StreamingSpeechBackend (load → stream audio → partials → finish → close)
interface SpeechEngine {
    val modelId: String
    suspend fun load()                                   // heavy; done once per selected model, off main
    fun start(sessionId: Long): Flow<SpeechEvent>        // Partial(text) … Final(text) | Error
    fun acceptAudio(samples: FloatArray)                 // real engine only; the fake ignores this
    suspend fun stop()                                   // stop capture → engine emits Final once
    fun cancel()                                         // drop everything; no Final
    suspend fun release()
}

// models/ — modeled on the fork's RecognitionModelCatalog (artifacts with size + sha256)
interface ModelStore {
    val models: StateFlow<List<ModelState>>              // NotInstalled | Downloading(p) | Installed | Active
    fun download(id: String); fun cancel(id: String)
    fun activate(id: String); fun delete(id: String)     // delete(active) is rejected
}

// ime/ — the only code that touches InputConnection
class EditorBridge(private val ic: () -> InputConnection?) {
    fun setComposing(text: String, owner: Long)          // marks provisional text as owned by a session
    fun commit(text: String, owner: Long)
    fun discardComposing(owner: Long)                    // removes only text this session still owns
}

6. Voice session state machine

  • Every transition that leaves Listening or Finalizing increments sessionId. Events whose ID does not match the current session are dropped. This mirrors the session-token approach in the concept 4 mockup and the voice fork's insertion-safety spec.
  • Cancelled discards provisional text through EditorBridge.discardComposing(owner). Committed text is never removed. The voice fork instead keeps partial text on cancel; our requirement is the opposite, which is why we write this part ourselves.
  • The current mode, Keys or Voice, persists in SettingsStore. If the keyboard opens in Voice mode and auto-start is on, it starts a new session.

7. Editor safety rules

  1. Provisional speech appears only as composing text. It becomes real text only when the final transcript arrives.
  2. Before any write, check that the session, the editor (from EditorInfo and field ID), and the selection are the ones this session started with. If they differ, cancel instead of writing.
  3. onFinishInputView and onStartInput with a new editor cancel the active session.
  4. Never commit a final transcript twice. The controller marks the session completed before calling the bridge.
  5. Password and other sensitive fields (TYPE_TEXT_VARIATION_PASSWORD, IME_FLAG_NO_PERSONALIZED_LEARNING) disable voice mode and learning.

Saved terms do not change what the speech model hears. Use phrase rules for that. Contextual biasing, if a runtime supports it, is a later experiment.

9. Speech models and runtime

  • Runtime: the voice fork uses ai.moonshine:moonshine-voice, the official Moonshine Android library from Maven, for Moonshine. It uses sherpa-onnx for Parakeet and Nemotron. Using the Moonshine library directly means we write no custom JNI and need no NDK build for the first engine. Its license and APK-size impact still need verification.
  • First model: Moonshine Small streaming English (246 MB, quantized). Medium (450 MB) is the accuracy comparison. Measure both on the Samsung phone with real coding dictation.
  • Storage: filesDir/models/<id>/, outside the APK and git. Download to .partial, verify each artifact's SHA-256, then rename atomically. ModelCatalog pins URLs, sizes, and checksums, as the fork's catalog does.
  • Downloads: WorkManager with a foreground notification, so a download survives leaving the app. Cancelling deletes the partial files. The active model cannot be deleted.
  • Audio: AudioRecord at 16 kHz mono float. Optional WebRTC VAD can stop recording after silence; the fork uses android-vad.

12. Testing and verification

  • JVM unit tests cover the voice state machine, including rejection of stale sessions, as well as phrase rules, suggestions, layouts, and model-store state. They run quickly with ./gradlew testDebugUnitTest.
  • Lint: lintDebug must report zero errors. T3 provides Build debug APK and Android lint scripts.
  • Device checks run on T3_Fold_API_36 through T3 device_open and the pinned agent-device. Check the nine acceptance flows in docs/mock-spec.md: typing in a real field, voice entry, cancellation, and mode recall.
  • Later engine benchmarks: use a fixed set of recorded coding prompts to measure word error rate, real-time factor, first-partial latency, and memory for Small and Medium on the Samsung phone.

14. Risks and open questions

Compose inside an input method

The service needs its own lifecycle, saved-state, and view-model owners. Insets and height have to be measured precisely. Startup time must be checked on the Samsung phone. Fallback: use Android views for the key grid only.

Suggestion quality without FUTO's native engine

A Kotlin trie handles prefix completion well, but corrections such as edit distance and key proximity need tuning. Consider reimplementing proximity-aware correction later.

Moonshine runtime licensing and size

Verify the license of ai.moonshine:moonshine-voice and the model weights, the native library size for each ABI, and whether to ship only arm64-v8a.

Samsung-specific behavior

Check One UI's IME switching gesture and globe expectations, Fold inner and outer screen heights, and floating or split keyboard expectations.

Dictionary word-list source

Find an English and Dutch frequency list with a permissive license that can be bundled.
