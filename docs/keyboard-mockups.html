Keep “T3 Code” as written

The dictionary strip should distinguish the literal text from a suggested correction. Saving a technical term preserves its spelling and case.

  • Add an exact term such as T3 Code to the personal dictionary.
  • Keep the literal token easy to choose instead of forcing a correction.
  • For coding fields, leave automatic correction and rewriting off by default.

These demos illustrate keyboard dictionary behavior. Speech recognition may still mishear a term. Any phrase correction after dictation needs a separate, explicit rule.

Voice should leave room to edit

Opening voice starts simulated recording. Returning to keys cancels capture and pending transcription. Stop completes the transcript once, without sending the chat message.

The selected local model remains manageable through a small model/settings control. Download and remove actions belong in settings, not an expanded panel over the editor.

All panel heights are design targets. They exclude Android navigation/safe-area insets and still need testing on the Samsung phone.

Reference and prototype limits

Layout references: FUTO Keyboard, Samsung's published keyboard examples, and the Moonshine voice-input fork. The globe position follows the S24 example already inspected in our comparison page. These are original HTML mockups, not copied keyboard implementations.

Model choices, sizes, and readiness labels are illustrative unless verified in the reference comparison. The controls simulate recording, transcription, model downloads, dictionary suggestions, and language switching. No microphone or real speech model is used. English speech remains the first target. Changing a typing language does not imply a multilingual speech engine.
