# Lowkey

**[Download Lowkey for Android](https://github.com/opstudio-eu/lowkey/releases/latest/download/lowkey.apk)** (Android 9 or later). Open the downloaded file on your phone to install it; Android asks once to allow installs from your browser. After that, Lowkey updates itself. Release notes and checksums are on the [releases page](https://github.com/opstudio-eu/lowkey/releases/latest).

**Lowkey Keyboard** is a slim Android keyboard with on-device voice input. Speech recognition, suggestions and autocorrect run on the phone; nothing you type or say leaves it. The app only goes online to download the speech models and keyboard languages you choose and to check for updates. It is a selectable input method plus a Compose companion app for setup, speech models, the dictionary and settings. Voice mode is one row with an in-keyboard model picker.

Lowkey is a personal project, published as source and signed APKs. It is not on the Play Store.

## Install and update

Lowkey needs Android 9 or later. Signed APKs are attached to each [release](https://github.com/opstudio-eu/lowkey/releases).

Download [`lowkey.apk`](https://github.com/opstudio-eu/lowkey/releases/latest/download/lowkey.apk) (always the newest version; the [latest release](https://github.com/opstudio-eu/lowkey/releases/latest) page has the release notes), optionally check its SHA-256 against the release notes, and open it. Android asks once to allow installs from your browser or file manager. Then open **Lowkey** and follow the setup steps to enable the keyboard and allow the microphone.

**Updates (0.5.1):** Lowkey updates itself; no other app is needed. About once a day, and when you open the app if the last check is more than 6 hours old, it reads the `update.properties` file of the latest release (version, APK link, size and SHA-256). A newer version shows a notification and a card on the Home page; tap **Update** to download it, check its size and SHA-256, and hand it to Android's installer. The first time, Android asks you to allow Lowkey to install apps (*Install unknown apps*) and to confirm the update. On Android 12 and later, once Lowkey has installed a version itself, the next updates install without that confirmation (tested on Android 16); older Android versions ask each time. The app closes while it updates; the keyboard keeps working, and your settings, dictionary and models stay. **Since 0.5.3** the download keeps going when you leave the app, with a progress notification. If Android then needs you to confirm, a *ready to install* notification opens its installer, as does **Install** on the card when you return. Versions 0.5.1 and 0.5.2 lose the download when you leave the app, so stay in Lowkey until Android's installer asks to confirm. Android also refuses any APK not signed with Lowkey's key. **Settings → Updates** has **Check now** and turns the automatic check off; with it off, Lowkey only goes online for model downloads. On Android 13 and later the notification needs the notification permission, which that section can ask for; without it, new versions show only on the Home page. Versions before 0.5.1 have no updater: install 0.5.1 once by hand.

Updates install over the previous version and keep your settings, dictionary and downloaded models. [Obtainium](https://github.com/ImranR98/Obtainium) also works with `https://github.com/opstudio-eu/lowkey` if you prefer it.

## Features

- **Speech:** OpenAI Whisper models run on the device through [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 1.13.8 and ONNX Runtime 1.31.0. Whisper transcribes after Stop; the final text is committed once. Switching to keys, hiding the keyboard, changing editor, moving the cursor, or opening the model picker cancels the capture.
- **Models (0.5.0):** Whisper tiny, base and small (English-only and multilingual, including Dutch), Whisper Turbo (large-v3-turbo, multilingual, 1 GB) and Distil-Whisper Large v3.5 (English, 1 GB), all MIT licensed and downloaded on request. sherpa-onnx is built for speech recognition only by `scripts/build-sherpa-onnx.sh`: its official Android builds include text-to-speech, which statically links GPL code. The library links ONNX Runtime 1.31.0, taken from the native-only Android archive that sherpa-onnx uses ([csukuangfj/onnxruntime-libs](https://github.com/csukuangfj/onnxruntime-libs/releases/tag/v1.31.0), pinned by SHA-256). Unlike Microsoft's Maven package it has no Java telemetry transport, so ONNX Runtime's telemetry stays off. Version 1.31.0 also avoids the SIGILL crash of ONNX Runtime 1.23.2 on CPUs with SME but not SME2 ([onnxruntime#26377](https://github.com/microsoft/onnxruntime/issues/26377)). Version 0.5.0 removed the Moonshine, Nemotron, Parakeet, Cohere and Orukeet models; their downloaded files are deleted on the first start.
- **Dictionary:** saved terms drive suggestions and restore exact casing in dictated text, for example `t3 code` → `T3 Code`. This can be turned off. Spoken-phrase rules stay opt-in.
- **Audio:** the microphone uses `AudioRecord` at 16 kHz mono. Debug builds include four `espeak-ng` test clips (`app/src/debug/assets/test-clips/`). Select them in **Settings → Diagnostics → Dictation audio** to dictate on an emulator without a microphone.
- **Keyboard languages (0.5.6):** English (US) is built in. Dutch, Polish, English (UK), German, French, Spanish, Italian, Portuguese (Brazil and Portugal), Swedish, Danish, Norwegian (Bokmål), Finnish, Czech, Croatian, Slovenian, Romanian, Lithuanian, Latvian and Russian download on request (0.4–5.2 MB each) under **Settings → Keyboard → More languages**. A downloaded language is turned on at once, and its layouts appear under Keyboard layouts. Each language has its own key layout, offered first (QWERTY, QWERTZ with Ü Ö Ä for German, AZERTY for French, Å Ä Ö for Swedish and Finnish, Æ Ø Å for Danish and Norwegian, Ñ for Spanish, ЙЦУКЕН for Russian), its own accents first on long-press (Polish: hold A for ą, C ć, E ę, L ł, N ń, O ó, S ś, Z ż and ź), suggestions and autocorrect. Words typed without accents get them (`zolw` → `żółw`, `konnen` → `können`), and completions ignore missing accents (`zol` offers words starting with `żół`). Polish also restores the accents of common words that its word list holds in both spellings (`juz` → `już`), and German capitalizes nouns typed in lowercase (`zeit` → `Zeit`). Downloads come from the same pinned AOSP commit as the built-in lists, are checked against their SHA-256 and size, and are converted on the phone. The languages are listed in `app/src/main/assets/dict/languages.txt`; adding one there is a data change. **Voice language → Same as keyboard** makes multilingual Whisper models dictate in the language the keyboard is set to (switching reloads the model). Latin-script languages also offer the alternative layouts below. Bundling all 21 lists would have added about 19 MB to the 88 MB APK; instead Dutch moved out of it too, which makes the APK 0.8 MB smaller. If Dutch was enabled before 0.5.6, when it was built in, it downloads again by itself after the update, as does any enabled language whose word list is missing.
- **Autocorrect (0.4.10):** suggestions and autocorrect use the AOSP LatinIME word lists (Apache 2.0): about 160,000 English and 178,000 Dutch words with frequencies. `scripts/build-dictionaries.py` rebuilds them from a pinned commit and SHA-256. A keyboard-aware edit distance (on each language's own layout since 0.5.4) handles neighbouring keys, swapped letters, doubled letters, missing accents and missing apostrophes. It also considers missing or extra first letters and gives closer spellings more weight against word frequency. Space and punctuation apply corrections. The built-in vocabulary includes autocomplete and autocorrect word forms missing from the older AOSP lists. The AOSP whitelist supplies contractions such as `dont` → `don't`. Saved terms, a built-in tech and chat vocabulary, code-like tokens, and capitalized names are protected. Pressing Backspace right after a correction restores what you typed. Each keyboard language uses its own list, and next-word prediction is not implemented. See [the automatic correction checks](docs/demos/automatic-correction-verification.md).
- **Clipboard:** when there is no word before the cursor, the top strip shows the current clipboard instead of dictionary terms. Tap to paste text exactly as copied. Image clips show a thumbnail and paste into editors that accept their image type. Other editors show that images are unsupported. Word suggestions return as you type. Clearing the system clipboard clears the preview. Password and private fields hide clipboard previews; clips marked sensitive hide their contents until pasted. The keyboard keeps no clipboard history. See [the clipboard checks](docs/demos/clipboard-verification.md).
- **Suggestion refresh fix (0.4.9):** word buttons stay visible while new suggestions are computed. The clipboard change had cleared these buttons on every refresh, cancelling taps already in progress. See [the failing and passing native check](docs/demos/autocomplete-verification.md).
- **Keyboard layouts (0.5.5):** Settings → Keyboard → Keyboard layouts turns on letter layouts per language: QWERTY, AZERTY (French and Belgian, with the apostrophe next to N), QWERTZ (German and Central European), Dvorak and Colemak. Turning one on doesn't switch to it. Tap the globe key to go through them in the order shown, or long-press the space bar for a chooser that lists every enabled keyboard and switches with one tap; long-pressing the globe key still opens Android's picker for other keyboard apps. The space bar names the language and, unless it is QWERTY, the layout (`EN · AZERTY`), and TalkBack announces each switch. A layout changes only the letter keys: suggestions and autocorrect follow the language, and autocorrect treats the keys next to each other on the current layout as likely slips. Number shortcuts sit on whichever keys form the top row, accents stay on their letters, and Shift and Backspace stay a key and a half wide. Existing settings carry over as QWERTY. **Since 0.5.6** every keyboard language from Keyboard languages above is listed, with its own layout first (German's QWERTZ has Ü, Ö and Ä keys, so plain QWERTZ isn't offered again); languages not written in the Latin alphabet, such as Russian, have only their own layout. Autocorrect judges slips by the keys of the layout in use and accents by the language.
- **Number shortcuts (0.4.8):** hold a top-row letter (Q–P on QWERTY) to open a large number preview for 1–0, then release to insert the digit. Short taps type the letter. Cancelling the hold inserts nothing. No extra row or keyboard height; works in English and Dutch with Shift or Caps Lock on.
- **Accents (0.4.24):** hold a letter that has accents to open a row of choices above it: e (3 é è ê ë ē ę ė), a, i, o, u, y, c, n, s and z. The first choice is selected (the number on Q–P, otherwise the most common accent); slide sideways to pick another and release to type it. Near the right edge the row opens to the left so the first choice stays under your finger. Sliding off the row and key cancels, and sliding back selects again. Shift and Caps Lock type capitals (É), and ß stays ß. Each accent is also a custom accessibility action on its key. `scripts/check-keyboard-touch.sh <serial> accents` checks it with real touch input.
- **Model retention (0.4.5):** Settings → Voice → Keep model loaded offers immediate release, 30 seconds, 2 minutes, 5 minutes, 15 minutes, or until the app process ends. The default is 2 minutes of idle time after dictation finishes or is cancelled, including while keys stay visible. Starting another capture cancels the expiry. Changing the setting uses time already spent idle. Recording and final transcription never expire; changing model/language or Android memory pressure can release resources sooner. Downloaded model files stay installed. Models, Voice settings, and the test sheet show actual loaded/in-use state.
- **Keyboard lab (0.4.5):** tap Test keyboard in the top bar on any companion page. A sheet opens a focused test field and the real keyboard over the current page. Close it to return to the same page and scroll position. Its shared draft and selection survive reopening, navigation, and activity recreation. Clear and Copy act only on the test draft; nothing is sent. The original Try it page remains available for multiple editor types.
- **Fast deletion (slider 0.4.20, hold-only 0.4.21):** a tap on Backspace deletes one character when you lift your finger. Holding it no longer repeats: after 300 ms (or as soon as you slide up) a vertical slider rises from the key instead, and nothing is deleted until you slide. **Since 0.4.34** it rises over the keyboard and the app on both keyboards. **Since 0.4.35** it ends at the same height on screen from both: about 4 cm tall from the minimized bar, and shorter from the full keyboard, whose Backspace sits higher (less if the screen has no room). It fills like a gauge up to your finger: each notch erases one more word before the cursor, live in the field, and the dashed cap at the top erases everything before the cursor. Slide back down and the erased words reappear, so you can stop exactly where you want; lifting your finger keeps what the field shows. **Since 0.4.36** words count from where your finger touched the key, so the first word goes after a short slide (about 2 mm), and the steps follow one smooth curve: the first word gets about 3 mm, and each next word a little less, speeding up toward the top without a sudden change of pace. Short text spreads its words over the whole slider. A word only changes once the finger is 4 dp past its edge, so a finger resting on an edge doesn't flicker. **Since 0.4.37** text after the cursor always stays: put the cursor mid-text and slide to the top to erase only what comes before it (with the cursor at the end that clears the field, and the chip still reads Clear all; otherwise it reads All before cursor). The slider reaches up to 10,000 characters on each side of the cursor; with more before the cursor, the top still erases all of it, but only on release, since it can't be brought back; it doesn't start with a selection or in editors that don't report their text.
- **Typing responsiveness (0.4.8):** each finger keeps its own key press, including overlapping presses on the same key. Spelling search uses precomputed neighbour lookups, reused edit-distance rows, and candidate traversal without temporary pairs. The full dictionary index and cold spelling initialization run on its loader thread before publication. See [the typing regression checks](docs/demos/typing-and-number-verification.md) for measured emulator results and the remaining phone-verification limit.
- **Minimized keyboard (0.4.11):** with a physical keyboard connected, Lowkey Keyboard stays on screen even when Android's *Show on-screen keyboard* setting is off, so voice apps that only appear next to a visible keyboard, such as Wispr Flow, still show their button. It opens as one slim bar with Backspace at the right, for corrections while dictating. It works like the full keyboard's: a tap deletes one character, and holding it raises the same slider, drawn in its own window above the bar. Tap the keyboard button at its left to expand the full keyboard, and the chevron at the strip's far left to minimize it again. The chevron also works without a physical keyboard, for example on a phone. The choice is remembered across fields and restarts, separately with and without a physical keyboard: by default it opens minimized with one and full without one. Turn this off under **Settings → Keyboard → Show with physical keyboard**.
- **Backspace fan and swipe-down (0.4.29):** on the minimized bar, a tap on Backspace still deletes one character. On the bar it is a round button. Hold it, or drag more than about 2 mm, and a quarter-circle fan opens up and to the left around that button, with its wedges starting at the button's edge. Slide onto a wedge and release to use it: **up** erases words with the existing slider; **up-left** types a space, and further out **clears the clipboard history** (the clip chips, recent screenshots up to that moment, and the system clipboard, so the clip doesn't come back when the keyboard reopens); after a clear, that wedge becomes **Undo clear** until something new is copied; **left** runs the field's own action (Send, Search, Go, Next, Done), and further out types a **new line** (always shown; dimmed in single-line fields, where it does nothing). The outer ring shows full keys **for this field only**, split over its two columns: up-left (above Clear clips) opens the **numbers** (123), left (beyond New line) the **letters** (ABC). The next field opens minimized again. Releasing near the key cancels. The fan's action is the one the field declares, also in chat fields that hide it from Enter; where a field declares none, the fan sends a plain Enter key. Sliding straight up still starts the word slider at once, and sliding the slider back down below where it started brings the fan back without lifting your finger. The fan's commands are also custom accessibility actions on the key. On the full keyboard, press Backspace and slide **down** (about 36 dp, within 30° of vertical) to minimize: the key turns into a chevron while armed, and sliding back cancels.
- **Point into the text to delete back to a word (0.4.32, Android 14+):** hold Backspace and slide up into the word slider, then slide left off the slider into the text field (on the full keyboard before 0.4.34, by sliding past its top edge). The word under your finger and everything after it, up to the cursor, is deleted as you move. Slide to another word and the text comes back or more goes, with a light tick at each new word. Past the end of a line keeps that whole line; past the last word deletes nothing. A chip above Backspace shows how many words go. Release to keep it, or slide back over the keyboard to put everything back ("Release to cancel"). Word positions are read once from the editor when the slide starts (`InputConnection.requestTextBoundsInfo`), so you can point at where a deleted word was to bring it back. In a field that resizes as text goes, the text may move away from under the finger; the finger still points into the original layout. This works in fields built on Android's `EditText`, which most apps use. Jetpack Compose text fields and Chrome don't report word positions yet and show "Not supported here". The **Try it** page has an EditText for testing. While the finger is down every slider step stays reversible: with more than 10,000 characters before the cursor, the top is applied only on release.
- **Clipboard history (0.4.19):** the slim bar shows the last 10 clips as small one-line chips between the expand button and Backspace, newest first, with image thumbnails. The full keyboard shows the same chips in its top strip whenever no word is being typed. If the history is empty or the current clip is sensitive, the strip shows the single current-clip chip as before. The row starts at the newest item each time the keyboard opens and whenever something new arrives. Swipe sideways for older ones, tap one to paste it, or hold it to preview the full text or a large image above the keyboard. For images and screenshots, slide up onto the preview and release to open the image editor: crop, pen, rectangle, circle, arrow, straight line (snaps to horizontal, vertical or 45° within 5°), highlighter and text notes in six colors, an eraser that removes any mark it touches (0.4.23), and undo and redo. **Blur (0.4.25)** hides account numbers, names and addresses before sharing. It is a color: the frosted swatch after the six colors makes any tool blur instead of paint. With it, Pen, Highlight, Line, Arrow and outlines are drawn at a wide blur width (five times the thickness), so one drag with Pen blurs a line of text, and a filled rectangle or circle blurs its whole inside. The blur is baked into the saved PNG: the covered pixels are replaced by an opaque copy reduced to coarse cells, box-blurred and scaled back, with cells sized to the mark (a quarter of a brush's width or of a filled shape's short side, at least 1/96 of the image), so large text is smeared as much as small text. Each blur also covers marks drawn before it. Blur hides detail but is not a guarantee: for certain redaction, use a filled solid rectangle. Rectangles and circles have a small round **Fill** switch before the size stepper (an empty ring when off, a filled dot when on) that fills new shapes with the color or the blur; the eraser removes a filled shape from anywhere inside it. **Move and resize shapes (0.4.28):** a rectangle, circle, arrow or line you just drew stays selected, with a dashed box and round handles on its corners or ends. Drag it to move it, or drag a handle to resize it; a line still snaps to horizontal, vertical or 45°. With any of these four tools, tap a placed shape (its outline, or inside a rectangle or circle) to select it again, and tap outside it to deselect and draw. A drag that starts on the selected shape moves it rather than drawing a new one. A shape keeps its place among the marks while it moves, blurs included, and it can't be moved or resized out of the crop. Until the first move, a hint on the image explains this. Moves and resizes are undoable. Pen and highlighter strokes can't be moved, and notes can be moved but not resized. **Delete, rotate and restyle shapes (0.4.33):** a selected shape has a round trash button beside it, placed clear of its handles; Undo brings the shape back. A selected rectangle or circle has a rotate knob on a stem above its box (or another side, if that would be off the canvas): drag it to turn the shape about its middle, snapping to 0°, 45°, 90° and so on within 4°. A turned shape still moves, resizes from its corners (the opposite corner stays put), blurs, erases and exports turned, and it stops turning before it would leave the crop. With a shape selected, the colors, the Fill switch and the − / + thickness stepper change that shape (each change undoable), and new shapes follow. Shapes, blur shapes included, draw live under the finger while you drag. While a finger draws or drags a crop handle, a 2× loupe (0.4.22) shows the spot under it, with the brush outline in the drawing color. The loupe docks in a corner away from the finger (0.4.23), so it covers neither the hand nor the shape being drawn: by default the top corners, or the left (for a right hand) or right (for a left hand) corners under **Settings → Image editor → Loupe corners**. It starts in whichever of the two is farther from the finger and switches only when the finger comes near it. Undo and redo sit at the top right (also Ctrl+Z and Ctrl+Shift+Z or Ctrl+Y on a physical keyboard) and cover marks, note edits and moves, and crop changes. Pinch with two fingers to zoom in (up to 8×) and pan, also after cropping (0.4.25); a second finger cancels a stroke in progress, and **Fit** shows the whole image again. Android's Back closes the editor without attaching. A small − / + stepper at the end of the color row sets the line thickness, or the note size in Text mode, shown in pixels on the image; it applies to new marks. Notes wrap at 60% of the image width; in Text mode, drag a note to move it or tap it to edit or delete it. Like a chat app's image send screen, the editor has a caption field and **Attach**: it returns to the field you came from and inserts the caption and the edited image there (once, within five minutes). The image is also put on the clipboard, so it is the newest chip, and stays pasteable if that app doesn't accept images. Edits are saved as PNGs in the app's private cache; the newest five are kept. Copying an older clip again moves it to the front. Clips are captured whenever Lowkey Keyboard is the selected keyboard, even while it is hidden, and are kept only in memory until the app process ends. Images are copied into the app's private cache, because Android revokes access to a copied image once something newer is copied, and deleted when they drop out of the history or the app restarts. Password-manager clips marked sensitive are never kept, and the history is hidden in password fields. Image chips are dimmed in fields that don't accept images. Android doesn't put screenshots on the clipboard, so **Settings → Keyboard → Recent screenshots** (off by default; asks for access to photos) adds up to five screenshots from the last day from the Screenshots folder, merged into the chips by time. Tapping one copies it into the history, then pastes it.
- **Keyboard-first dictation (0.4.6):** enabled by default under Settings → Voice, including on upgrades. Editors open with keys. Tapping the mic starts recording in the compact voice row. Stop keeps that row visible while transcription finishes, then the final text is inserted and keys return for corrections. No-speech also returns to keys. Turn the setting off to use the earlier mode recall, auto-start, and continuous dictation options.

## Build

You need JDK 21 and the Android SDK (API 37) on `PATH`. The Gradle wrapper downloads Gradle and verifies its checksum.

```bash
./gradlew --no-daemon testDebugUnitTest assembleDebug lintDebug
adb -s <serial> install -r app/build/outputs/apk/debug/app-debug.apk
adb -s <serial> shell ime enable com.rheerkens.androidkeyboard/.ime.SlimKeyboardService
adb -s <serial> shell ime set com.rheerkens.androidkeyboard/.ime.SlimKeyboardService
```

The build uses Gradle 9.8.1, Android Gradle Plugin 9.4.1 with built-in Kotlin (Kotlin 2.4.21), compile and target SDK 37 (minSdk 28), and Compose BOM 2026.09.00. The application ID `com.rheerkens.androidkeyboard` and the service name date from the project's first version and stay unchanged, so updates keep installing over existing installs. Debug builds are signed with your local debug key; install them only on emulators or test devices.

## CI and releases

GitHub Actions (`.github/workflows/ci.yml`) runs the leak check, unit tests and `assembleRelease` on every pull request and push to `main`, signs the release APK, and attaches it to the run. Runs without the signing secrets, such as pull requests from forks, attach an unsigned APK that can't be installed.

A push to `main` whose `versionName` has no `v<versionName>` release yet publishes one, with one APK, `lowkey.apk` (the same name in every release, so the README's download link always serves the newest version), its SHA-256, and the `update.properties` file the in-app updater reads. Releases before 0.5.4 also attached the same APK as `lowkey-<version>.apk`. To release, bump `versionName` and `versionCode` in `app/build.gradle.kts` in the pull request.

### Signing

Releases are non-debuggable builds signed with the release key (certificate SHA-256 `27f8bcb8…42d3d9`) using APK Signature Scheme v3. The earliest builds were signed with a development debug key; `signing/rotation-lineage.bin` is that key's signed approval of the release key, so a release also installs over those builds and keeps their data. Key rotation needs Android 9, hence minSdk 28.

`scripts/sign-release-apk.sh <unsigned.apk> <signed.apk>` signs and checks an APK. It reads the keystore path and password from `RELEASE_KEYSTORE` and `RELEASE_KEYSTORE_PASSWORD`; CI restores them from the `RELEASE_KEYSTORE_BASE64` and `RELEASE_KEYSTORE_PASSWORD` Actions secrets. The keystore never enters the repository.

## Keeping private details out

The repository is public, so commits, pull requests, CI logs and release notes must not contain private hostnames, network addresses, home-directory paths, personal email addresses or screenshots that show them. `scripts/check-leaks.py` enforces this:

- **Before pushing:** enable the hook once per clone with `git config core.hooksPath .githooks`. The pre-push hook checks the commits, author and tag metadata and ref names of everything you push that the destination doesn't have yet, using the general patterns plus a required private list of exact strings in `~/.config/lowkey/leak-denylist` (one per line, kept outside the repository). It refuses refs that point to anything other than commits.
- **In CI:** the same check runs on the files, the new commits, the pull request title, body and branch (read from the event file, so they never appear in the log), every entry of the built APK, and the generated release notes before a release is published. The private list comes from the `LEAK_DENYLIST` Actions secret; pull requests from forks get only the general patterns. Findings name the file and line, never the matched text, because CI logs are public.
- **Reviewed files:** binary assets and third-party license texts are listed with their SHA-256 in `.leak-allowlist` after a manual review (`scripts/check-leaks.py allow <path>`). Any change to such a file needs a new review.

`scripts/test_check_leaks.py` tests the check. Commit with your GitHub no-reply address (`git config user.email <id>+<user>@users.noreply.github.com`). Keep screenshots and demo videos out of git; attach them to pull requests after checking them.
